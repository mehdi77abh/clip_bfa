# =============================================================================
# requirements-vlm-transfer.txt — extras for vlm_transfer/ (README.md §6)
# =============================================================================
# Installed by setup_env.sh by default (skip with --no-vlm).
# torch / torchvision / transformers / sentencepiece / protobuf / numpy /
# Pillow come from the core env (requirements-vastai.txt).
#
# NOT listed here on purpose:
#
#  * open-flamingo==2.0.1
#      Its PyPI metadata hard-pins torch==2.0.1 and sentencepiece==0.1.98 —
#      a plain `pip install open_flamingo` would DOWNGRADE the CUDA torch
#      build.  setup_env.sh installs it with `--no-deps`; its actual
#      runtime imports only need torch, transformers, open_clip, einops and
#      einops-exts, all present here.
#
#  * eva-clip
#      Not on PyPI and the upstream EVA-CLIP repo ships no setup.py, so it
#      cannot be pip-installed.  setup_env.sh clones baaivision/EVA and
#      puts EVA-CLIP/rei on sys.path via a site-packages .pth file (this is
#      what makes `import eva_clip` work for BLIP-2).
#
#  * apex / xformers / mslk
#      NOT REQUIRED.  `import eva_clip` prints "Please 'pip install apex'"
#      and "Please 'pip install xformers'" as OPTIONAL-dependency hints —
#      they only enable fused/faster ops and nothing here uses them.
#      Do NOT `pip install apex`: the `apex` on PyPI (apex-0.9.10dev ->
#      cryptacular, scons, C extensions) is a password-hashing library, not
#      NVIDIA Apex, and fails to build.  If NVIDIA Apex is ever wanted it
#      comes from git+https://github.com/NVIDIA/apex, never from PyPI.
# =============================================================================

# open_flamingo runtime imports
